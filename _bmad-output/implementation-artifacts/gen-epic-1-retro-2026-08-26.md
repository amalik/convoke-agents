## 3. What went well

- **AC6's arithmetic was derived, not recalled, and right first time.** 11 total write ops, exactly 1
  in the extracted range, 10 after, new module at 1 — counted with `scripts/audit/install-scope-check.js`'s own
  `WRITE_OP_RE` after a first attempt with a hand-rolled regex gave 41 and was discarded.
- **`install-scope-check` did the job it exists for, twice.** When the Round 2 remediation added an
  `fs.rename`, it went red with `DELTA: +1` and forced a written review of the new write before the
  snapshot moved. When the T77 row was filed with two unescaped `|`, `backlog-integrity` failed on
  arity within seconds. Both are gates that made someone *look*.
- **The two-oracle design in Task 1 earned itself.** It read as ceremony. Then the mutation matrix
  showed that killing schema detection was **invisible** to the v6.1.0 oracle — the committed
  manifest's header *is* `V610_HEADER`, so overwriting it is a no-op — and caught only by the legacy
  oracle. A single-oracle check would have certified a broken extraction as byte-identical.
- **AC4 asserting the write op rather than content was vindicated by measurement.** With the guard
  removed, the live manifest *was* rewritten and `git status` stayed clean throughout, because
  generator output is byte-identical to the committed file. Content-based and `git`-based assertions
  are both blind here.
- **The `!isSameRoot` guard broke nothing.** Six live `PACKAGE_ROOT` callers, zero regressions.

## 4. What did not

### 4.1 Three attempts at one defect, each written against the code's model of the file

The dominant pattern, and Round 3's diagnosis:

| Attempt | What it guarded | Why it failed |
|---|---|---|
| R1 | a byte (`existingRaw !== ''`) | tested non-emptiness, not usability; one dropped header line reproduced the defect |
| R2 | a string shape (three-state classifier) | **deleted 41 of 53 rows** while returning *"other modules preserved"* |
| R3 | a two-item allowlist | its `legacy` limb matched **none** of the three headers in this repo's history (62 blobs, 21 commits) |

The sibling at `refresh-installation.js:518-522` does what none of the three did: it **parses** and
asks whether the column it needs is present. Every attempt reasoned from the module's own row
builders instead of from the file's actual history.

Same shape in the specification phase: R1 specified an md5 check that **passed on the defective
code**; R2 relocated the same tautology (`git diff --exit-code` returned exit 0 after a wrong-root
run wrote 13,391 bytes); R3 inverted it into a check that goes **red on a correct implementation**.

**Generalisation:** when a check keeps being wrong, the fault is usually the *model* it encodes, not
its predicate. Read the artifact, not your memory of the artifact.

### 4.2 The operator was the control, twice

| Moment | What the process said | What the operator's question found |

Both times the process had declared itself finished. Neither round was scheduled by any mechanism.

### 4.3 The rule was written down and violated by the agent that had read it

`code-review-convergence:164` triggers Round 2 on *any* HIGH in Round 1. Round 1 produced one.
Round 2 was skipped, and the justification — *"the HIGH is fixed and its fix is falsifiable"* — was
written into a pushed commit. The rule's trigger is the **existence** of a HIGH; fixing it is the
expected response, not an exemption. **132 lines shipped unreviewed**, precisely the category
`:190` names.

`feedback_verification_basis` already recorded the identical skip from a prior session, also caught by
the operator asking. **Two instances, one written lesson, zero prevention.**

### 4.4 Root cause, verified: the backstop the rules claim exists, does not

`project-context.md:534` asserted that CI catches this bypass — *"a story cannot reach `done` without
a review record"*. **Verified 2026-08-26: no such gate exists.** No job in `ci.yml` asserts a review
record or a test-touch; no script in `scripts/audit/` mentions review.

This is a `documentation-claims-must-be-derived` violation **inside the file that defines that rule**,
and it is the mechanism by which the skip went undetected: the sentence told the reader a bypass would
be caught. Corrected in this session; the gate is filed as **T77**.

### 4.5 Two harness failures that nearly became reported findings

- A `perl -0pi` mutation silently **prepended** to line 1 instead of substituting, and the `node -c`
  guard passed it because a `ReferenceError` is a *runtime*, not a syntax, failure. Three confident
  "BLIND SPOT" verdicts were produced about tests that were fine.
- An earlier probe died on `Cannot find module 'fs-extra'` — a scratch harness with no dependencies.

Caught only by the house heuristic: **if all rows of a matrix agree, suspect the harness first.**

### 4.6 A row filed against its own epic's instruction

`convoke-epic-generated-artifact-writes.md:58` states: *"If the deferred CI drift gate is ever taken
up, it belongs here as 1.2 rather than in the Fast Lane."* T74 **is** that gate, and it was filed in
the Fast Lane hours after that document was read to write the story's References. Same failure mode as
§4.1.

## 8. The one-line lesson

**Every defect in this epic was a verification defect.** The code worked; the proofs did not. When a
check is the evidence for a claim, the check is the deliverable — and a rule saying so is not a
control. Twice now, the control has been the operator asking a question.
