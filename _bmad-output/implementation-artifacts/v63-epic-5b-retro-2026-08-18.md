## The central finding

**Three of the eleven anti-patterns in our own registry recurred during the release the registry was
written for.**

| Entry | How it recurred |
|---|---|
| **AP-3** — Round 1 patches introducing new HIGH-severity regressions | Three consecutive times on BUG-16. Each fix for a review finding introduced a new defect that the next round caught |
| **AP-7** — Overpromising by referencing unbuilt machinery | The playbook's §(a) scoped a PF1 validation battery that §(d) records as retired. Caught at Winston's sign-off, in the document that lists AP-7 |
| **AP-11** — Count drift in cross-spec narratives | "31 sites remain" was wrong by ~30% on the day it was written |

The registry was correct, complete, and available throughout. It was consulted **after** the fact.

**I96** — the Sprint 0 checklist whose entire purpose is forcing that registry to be read at the
*start* of a release — shipped in the final story of the release it was meant to protect.

This is the same shape as every other failure this week: **the check existed and nothing made it
fire.** Not a knowledge problem. A triggering problem.

## What went well

**Outside eyes found what inside eyes could not.** Two of the three highest-value findings of the
week came from outside the working environment:

- The **second machine** — clean, no stale global, no history — surfaced BUG-16 in a single run,
  after two adversarial review rounds and a full suite had missed it. Machines with history hide
  defects.
- The **external validator** produced one sentence — *"If everything is fine, I shouldn't have
  warning messages"* — that is better product feedback than anything generated internally in three
  days. It became BUG-19.

**Adversarial review earned its cost, repeatedly.** Every round returned something real, including
three that found defects in fixes written minutes earlier. Round 1 on BUG-10 found that changing an
emitted string had silently broken a workflow matcher; Round 2 found the guard written to prevent
that was blind to 1,000 lines; Round 2 on BUG-16 found the publish job could never have
authenticated at all.

**Rules added mid-flight actually fired.** The review trigger and commit-preparation rule were
written on the morning of the 15th and were load-bearing within hours. The set-equality check caught
a misplaced edit within a minute of first existing.

**Withdrawing beat shipping.** The bespoke CLI-guidance gate was written, reviewed twice, and
withdrawn rather than patched a third time. A gate printing PASS over unscanned code manufactures
exactly the false confidence the work existed to remove.

## What did not

**Four failed publishes, three causes, and the real one took a review to find.** `ENEEDAUTH` (no
secret) → `badges:check` (a date stamp) → `EOTP` (account, then package 2FA) → `404`. The 404 was
diagnosed as trusted-publisher misconfiguration and chased through npm's settings three times. The
actual cause: the publish job pinned Node 20, which bundles npm 10.8.2, which has **no OIDC registry
authentication** — so with the token removed it published anonymously, and npm returns 404 rather
than 403 for unauthorised writes. Provenance *signing* is a separate, older feature, so every attempt
signed a Sigstore statement and looked authenticated right up to the write.

**Verification kept passing while proving nothing.** Four instances, each producing a confident wrong
answer: a piped exit code reading `tail`'s; `${...}` parsed as a grep interval expression, raising a
false alarm against a correct build; an `npx -p` probe that proved the global was bypassed and was
reported as proving the right version was served; a mutation harness with no `node_modules` where all
four cases died identically. A fifth — a column-arity check flagging 71 correct rows — was caught only
because it was run before shipping.

**Line-level staging destroyed backlog records twice.** `c841fcd2` dropped the BUG-16 row while
shipping BUG-16's own fix; `3a3de195` dropped T35 (an *open* risk item) and T39 while claiming to
have repaired them. A modified row appears as `-old` / `+new`; staging the `-` side alone deletes it,
silently, with every check green. The instruction to stage line-by-line came from the agent, because
a concurrent session shared the file.

**4.0.0 shipped hand-published, without provenance.** Eight minutes after the CI job failed. That is
T35's seventh instance, the attestation cannot be added retroactively, and the published tarball
predates the publish-path fix.

**A publish gate protected a file nobody reads.** `badges:check` blocked the release over
`docs/badges.json`, whose last consumer was deleted by the I156 README rewrite and which does not
ship at all.

**Concurrent sessions cost three ID collisions** (BUG-12, T33, T36 — the last already committed
before it was noticed) and required line-level staging, which caused the row losses above.

## Significant discovery — the playbook has a sequencing defect

**Story 5B.2 runs the retrospective *before* Story 5B.3 ships the release.** That ordering guaranteed
the initiative's own retro could not observe its release, and it is why the richest material of the
week went unrecorded until now. The `host_framework_sync` playbook, signed off on 2026-08-16,
inherits the same ordering in WS5.

**Recommendation:** amend playbook §(c) WS5 so the retrospective step follows ship, or splits — a
planning retro before, an execution retro after. This is the second defect found in a document signed
three days ago, and both were found by reading it rather than using it.

## Key takeaways

1. **Checks that exist but do not fire are indistinguishable from checks that do not exist.** The
   registry, `docs:audit`, the review rule, the I96 checklist — every one was correct and silent.
2. **A verification is not evidence until it has been seen to fail.** This cost more time than any
   defect in the product.
3. **The cheapest high-value test is an environment with no history.** One clean machine beat two
   adversarial review rounds and 1,646 tests.
4. **The best product feedback came from the one person who had never used the tool.** One sentence,
   unprompted, in a two-minute session.
