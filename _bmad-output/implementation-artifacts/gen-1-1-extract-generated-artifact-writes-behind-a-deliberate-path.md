> ## 🛑 RETURNED TO BACKLOG 2026-08-24 — the premise is wrong. Do not implement as written.
>
> A two-layer pre-implementation review found **~9 HIGH findings**, and they are not polish — they
> invalidate the story's factual basis. See the Change Log entry below and **T54** in the lifecycle
> backlog, which carries the corrected analysis.
>
> **What is false in the text below:**
> 1. **"Two writes."** There is ONE. `mergeTaxonomy` short-circuits on a steady-state merge and
>    writes nothing — asserted by `tests/unit/taxonomy-merger.test.js` (*"I140: a steady-state merge
>    does not write"*) and confirmed by mtime measurement. Guarding it buys nothing.
> 2. **"`refreshInstallation` is the only generator."** False for both files. `bootstrapTaxonomy`
>    in `scripts/migrate-artifacts.js:149` is a separate implementation shipped as the
>    `convoke-migrate-artifacts` bin — so a deliberate taxonomy path ALREADY EXISTS. The manifest is
>    also written by `migrations/1.0.x-to-1.3.0.js` and `backup-manager.js`'s restore. The accurate
>    claim is narrower: refresh is the only *from-registry* generator of the manifest.
> 3. **"Regenerates the manifest from `agent-registry.js`."** It does not. It reads the existing
>    manifest, detects the schema from its header, preserves non-bme rows, and merges registry rows
>    into that — a function of the TARGET TREE's state. AC1 and AC2 are built on the wrong model.
> 4. **AC7 forbids the change the story requires.** `scripts/audit/install-scope-check.js:93` pins
>    `expected: 11` write ops in `refresh-installation.js` and passes at 11 today; the manifest write
>    is one of them. Extracting it drops the count to 10, failing a checker that runs in
>    `agent-surface-parity` — which is in `publish.needs`. **Task 2 as written red-lights CI and
>    blocks a publish**, and AC7 forbids touching the checker to fix it.
> 5. **`npm run generate:manifest` would ship to consumers** and, implemented naively, rewrite a
>    user's manifest with dev-tree values.
>
> **What survives:** one unguarded write (the manifest) that fires in a dev tree, whose fix must
> account for a pinned write-op count, a target-state-dependent generator, and a script that must
> refuse to run outside the package repo. Materially smaller than this draft.

## Story

As a Convoke maintainer,
I want the files Convoke generates to be regenerated by a command I run on purpose,
so that running the test suite never rewrites a tracked, shipped file behind my back — and so a stale generated file is something I can fix rather than something I discover.

## ⚠️ Read this before touching the code

**The obvious fix is wrong, and it was written down as the fix.** T54 originally prescribed
*"wrap both in `!isSameRoot`, the same shape as T50"*. **Do not do that.** T50 guarded the Vortex
`config.yaml` **stamp** — that is *state*, and skipping it in a dev tree costs nothing. These two
are **generated artifacts**, and `refreshInstallation` is their **only generator**:

- Nothing else writes `_bmad/_config/agent-manifest.csv`. `validator.js`, `backup-manager.js`,
  `catalog-generator.js` and `export-engine.js` only read it. Verified 2026-08-24.
- `mergeTaxonomy` is reachable only from `refreshInstallation` and two historical migrations
  (`2.0.x→3.1.0`, `3.0.x→3.1.0`). The comment at `refresh-installation.js:1110` records that
  **I137 wired it into refresh precisely because a fresh install ran no migrations and the file was
  therefore never created** — a clean install failed its own health check.

Guarding them would leave a dev tree unable to regenerate either file. An agent added to
`agent-registry.js` would go silently missing from the manifest, and I137 would be undone: a visible
surprise traded for an invisible one.

**The defect is that `npm test` is the trigger, not that regeneration happens.**

## Acceptance Criteria

**AC1 — Manifest generation has one implementation and two callers.**
**Given** the manifest-building logic currently lives inline in `refreshInstallation`
(`refresh-installation.js:639-794`, **156 lines**, depending on nine names from the enclosing scope:
`projectRoot`, `version`, `activeGyreAgents`, `EXTRA_BME_AGENTS`, `buildAgentRowLegacy`,
`csvEscape`, `header`, `preservedRows`, `changes`/`verbose`)
**When** this story completes
**Then** that logic lives in one module under `scripts/lib/`, called by **both**
`refreshInstallation` and a new deliberate entry point
**And** it is **behaviour-preserving**: the generated bytes are identical before and after, proven
by generating into a temp target from both callers and diffing.

*A copy would not satisfy this. One copy, two callers — the shape that worked for
`scripts/ci/downgrade-guard.sh`.*

**AC2 — A deliberate regeneration command exists.**
**Given** there is today **no way to regenerate the manifest except by running a refresh**
**When** this story completes
**Then** `npm run generate:manifest` regenerates `_bmad/_config/agent-manifest.csv` from
`agent-registry.js`, prints what changed, and exits 0 when nothing did
**And** it is documented wherever contributors are told how to add an agent.

**AC3 — Taxonomy creation keeps its I137 guarantee.**
**Given** I137 wired `mergeTaxonomy` into refresh because a fresh install runs no migrations
**When** the refresh-side call is changed
**Then** a **fresh install still creates `_bmad/_config/taxonomy.yaml`** — demonstrated against a
temp target, not argued
**And** if a deliberate path is added for taxonomy too, refresh remains a caller rather than being
replaced by it.

**AC4 — The refresh-side writes no longer fire in a dev tree.**
**Given** five test call sites pass `PACKAGE_ROOT` deliberately, to exercise dev-environment skip
branches — `refresh-installation-enhance.test.js` (**5** calls) and
`refresh-installation-artifacts.test.js` (**2** calls)
**When** this story completes
**Then** a full `npm test` leaves `_bmad/_config/agent-manifest.csv` and
`_bmad/_config/taxonomy.yaml` **byte-identical**
**And** that is asserted by a test, not by someone running `git status`.

**AC5 — Each guard is demonstrated FAILING before it is trusted (NFR10).**
**Given** both files are currently byte-identical to what a refresh produces — measured 2026-08-24
by md5 before and after a real dev-tree refresh, **both unchanged** — so a guard added today looks
identical to no guard at all
**When** the guards are accepted
**Then** each is shown failing by **mutation**: remove the guard, observe the test fail, restore it,
observe it pass. Output recorded.

*This is the load-bearing AC. T50's guard was accepted on exactly this evidence and nothing weaker
would have distinguished it from a no-op.*

**AC6 — OPERATOR DECISION: does CI gate manifest drift?**
**Given** a manifest that disagrees with `agent-registry.js` is a real defect — it is what I137 and
the T25 fresh-install work exist to prevent
**When** this story completes
**Then** the operator has decided **either**:
- **(a)** CI fails when `npm run generate:manifest` would change the file — a drift gate. Catches a
  forgotten regeneration at PR time; **also blocks a release** if it lands in `publish.needs`; **or**
- **(b)** no gate — regeneration stays a documented step, and drift is caught by review.

**And the decision is recorded with its reasoning.** Do not choose (a) silently: it makes an
unregenerated manifest a release blocker, which is the same severity call `dist-1b-1` made for
`docs:audit` and should be made deliberately, not inherited.

**AC7 — Nothing else in `refreshInstallation` changes.**
**Given** the function is large and carries several unrelated guards
**When** this story completes
**Then** the diff touches only the manifest block, the taxonomy call site, and their new callers
**And** the existing dev-environment skips (agents, workflows, submodules, Enhance, Artifacts, Gyre,
guides, skills, orphan cleanup) are **unmodified** — assert by diffing that no other
`isSameRoot` branch changed.

**AC8 — The remaining writes are surveyed, not assumed clean.**
**Given** the T50 review found three further writes to `projectRoot` that are benign *today*
(`agents/*.customize.yaml` is create-if-absent; `.claude/skills/bmad-agent-bme-*/SKILL.md` is
gitignored; the `.claude/commands/bmad-agent-bme-*` delete matches nothing)
**When** this story completes
**Then** each is re-checked and its status recorded — *benign today* is exactly what these two were.

### §2 — Why this is a story and not a Fast Lane fix

T54 was filed as Fast Lane work with a one-line fix. The fix was wrong, and finding that out took
reading the I137 history. The real work is an extraction with a capability to preserve and a
severity decision to make. `dist-1b-1` began life as "a one-line grep fix" and ended as a shared
script, a CI job, a test file and two review rounds — this has the same shape, recognised earlier.

### §3 — Rules that bind this story

- **`external-claims-must-be-executed-or-hedged`** — every claim here carries a measurement. Any new
  claim needs a new one.
- **`verification-must-be-falsifiable` / NFR10** — AC5 exists because both files are currently
  in sync, so a guard is indistinguishable from a no-op without mutation.
- **`derive-counts-from-source`** — the manifest is generated; nothing may hardcode agent counts.
- **`code-review-convergence`** — R1 fires when the commit plan is prepared.

### §4 — Out of scope

- The Vortex `config.yaml` stamp — already fixed under T50.
- Any change to `agent-registry.js` or the agent set.
- `convoke-doctor`'s version-consistency check, which reports ✗ on a dev tree **by design** (four
  modules sit at template `1.0.0` there).
