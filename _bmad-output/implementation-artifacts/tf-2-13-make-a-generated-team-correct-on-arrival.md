# Story 2.13: Make a generated team correct on arrival

Status: review

**Epic:** tf-epic-2 — Team Factory Guided Workflow (in-progress) · **Origin:** `T131` (6.0) + `T133` (3.0), both filed 2026-09-10 from the first end-to-end factory run (`tf-2-11`).

**Epic placement note.** `tf-epic-2-retrospective` already reads `done`, so this is the second story added to a retrospected epic (after `tf-2-12`). Recorded deliberately rather than left to look like drift, and the alternative was considered: an incident-driven mini-epic, per the `lint-epic-1` / `cov-epic-1` / `i97-bug-epic-1` / `ci-hygiene-epic-1` precedent. Epic 2's scope — *Guided Workflow: Factory Discovery & Generation* — genuinely covers generation correctness, so a third epic was judged worse than a recorded oddity. **Scope boundary.** `tf-2-12` made the flow **executable**. This story makes its **output correct**. It does NOT touch: `T136` (the `run:` blocks still cannot be pasted verbatim — shell transport, framework-wide), `T137`/`T138` (activation-validator hardening), `T128` (the terminal gate), `T127` (ruled 2026-09-11: accept v5 output), `T139` (`tf-epic-3`'s false completion).

## Story

As a framework contributor,
I want a team generated by the factory to arrive with a correct config path, unique command codes, a truthful file manifest, a real output directory and a populated agent persona,
so that a new team needs no hand-correction after generation, and the registry entry for a factory-built agent is not a hollow shell beside the hand-written ones.

## Context

`tf-2-11` drove the factory end to end for the first time and found the generated team wrong in six ways that only show up *after* generation succeeds. Every one was re-verified live on 2026-09-13 as a staleness pre-flight before this story was authored; all six are still present.

The persona defect (`T131`) is the one that decides whether the factory is worth using. **It was filed on a wrong premise and re-ruled on 2026-09-11:** it read as "the factory never ASKS for persona", which framed it as a collection problem blocked on NFR2, since `step-01-scope.md` sits at `Concept count: 3/3`. But `step-04-generate.md` §3a **already instructs BMB** to author a *"Persona section (role, identity, communication_style, principles)"* into every agent file. The factory commissions the persona and then reads an empty spec field instead. **It is a wiring defect, not a scope gap** — which is why this story adds **zero** operator questions and NFR2 never binds.

## Acceptance Criteria

1. **Given** a generated team's `config.yaml`
   **When** it is written
   **Then** `output_folder` carries the `{project-root}/` prefix, matching `step-02-connect.md:71`'s own documented template and every shipped module (`_gyre`, `_vortex`, `_team-factory`).

2. **Given** a team whose workflow names share their first two words
   **When** `module-help.csv` is written
   **Then** every `code` in the file is unique.

3. **Given** an agent spec carrying both `role` and `title`
   **When** its registry entry is built
   **Then** the entry's `title` holds the spec's `title`, not its `role`.

4. **Given** a completed generation
   **When** the file manifest is produced
   **Then** it lists every file that was created and no file that was not — specifically including `README.md`, the user guides and the workflow step files, and excluding any `SKILL.md` the generator did not write.

5. **Given** a team whose `integration.output_directory` is set
   **When** generation completes
   **Then** that directory exists on disk.

6. **Given** an agent file BMB has just authored
   **When** its registry entry is built
   **Then** `persona.identity`, `persona.communication_style` and `persona.expertise` are populated from that file, and the extractor reads **both** v5 `<persona>` XML and v6.3 markdown sections.

7. **Given** the repair
   **When** `npm test` runs
   **Then** 0 failures, the pre-existing skip count is unchanged, and each of AC#1-#6 has a test that has been demonstrated to fail before its fix.

- **T131's design is ruled** (2026-09-11): derive from the agent file. ### Traps this module has already sprung

- **`buildAgentEntry` is shared by `registry-writer` and `registry-appender`**, so Tasks 3 and 6 propagate to the add-agent path for free — the opposite of `T139`'s orphaned-appender shape, and worth preserving. Do not fork the helper to fix one caller.
- **Idempotency (NFR4) is scoped within-version.** Task 2's uniqueness must be deterministic for a given spec — a counter driven by iteration order breaks re-runs and express mode.
- **`createConfig` and `createCsv` are additive-only** and refuse to overwrite (`config-creator.js:26`, `csv-creator.js:28`). Task 8's throwaway cannot be regenerated in place; delete first.
- **Measuring the framework while your own artefact is on disk** produced two wrong counts during `tf-2-11`. Task 8's grep prohibition is not pedantry.

### Testing standards

`tests/team-factory/` uses `node:test`. All four target suites already exist. `project-context.md` rule `verification-must-be-falsifiable` makes Task 7's red-then-green demonstration mandatory, not optional.
