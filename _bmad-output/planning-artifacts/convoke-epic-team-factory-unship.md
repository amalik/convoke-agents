# Epic: Team Factory Unship (`tfu`)

**Operator ruling, 2026-09-16:** the Team Factory is **internal scaffolding, not a user-facing
capability**. It currently ships. This epic stops it shipping.

**Rows:** `T179` (2.0, `loom`, Open) — the unship. `T150` (5.7, `convoke`, Open) — the docs-audit
workflow-roster gap, bundled into `T179` on 2026-09-28 (`21ed0512`) because T179's own text already
claims *"The docs-audit roster counts and the `_team-factory` skill row move with it"* without naming
the row that carries them.

**Do it in one change, or not at all.** That clause is `T179`'s, and §"Ordering" below is the
mechanism behind it — thirteen constraints, each cited to the check that enforces it.

## Why this exists rather than a story in `tfr`

`tfr` (Team Factory **Repair**) closed 2026-09-16: `tfr-epic-1` and `tfr-epic-2` are both `done` with
retrospectives done, and its DoD is *"a contributor follows `add-team` start to finish… and the
terminal gate returns true."* Unshipping is not repair, and reopening a line closed with two retros
to carry the opposite intent would make one epic file mean two things. Operator chose a new epic
2026-09-28.

## What makes this worth doing rather than holding

The module that exists to generate teams has generated none that survived. Derive it, do not quote
this sentence:

```bash
node -e "const r=require('./scripts/update/lib/agent-registry.js');
console.log([...r.AGENTS,...r.GYRE_AGENTS,...r.EXTRA_BME_AGENTS].map(a=>a.id).join(', '))"
```

The result is Vortex's seven, Gyre's four, and `team-factory` itself. `docs/development.md:77-83`
already records the ruling and cites `T179` by name, so the repository currently documents a
capability as recommended **and** as withdrawn.

`T179` is scored 2.0 and says *"Not urgent — schedule it when the factory's status would otherwise
mislead someone."* That condition is a judgement call and this epic does not claim it has fired.
What this epic fixes is that the change was **priced as four edits and is not** — see below.

### Three findings that were not priced at all

**1. The Covenant cites it as a worked example, and the Covenant ships.**
`_bmad/bme/covenant/covenant-operator.md:130` and `:170` use Loom's `team-factory` / `add-team` as the
**"Good example"** for two Operator Rights; `:208` carries a scoped verdict on it. Both covenant files
are in `files[]`. Unshipping without replacing those examples leaves Convoke's normative document
demonstrating its own standard with a capability the operator cannot reach.

**2. Existing installs keep an orphan, permanently.**
The submodule *removal* loop is itself driven by `EXTRA_BME_AGENTS`
(the `// 2b1.` submodule copy loop in `scripts/update/lib/refresh-installation.js`). Empty the array and the loop never runs, so every
project that already installed `_bmad/bme/_team-factory/` keeps it, with a frozen `version:`.
`convoke-doctor`'s `discoverModules()` still finds it by `config.yaml`, so version consistency fails
**forever**, with the un-actionable remedy "Run convoke-update". This is defect `I137` in mirror image
and it needs a migration. It is invisible to this repository's CI, because CI never has a stale install.

**Split out at Round 1 as `T222`, and NOT in this epic.** It was AC#8 of `tfu-1-1` until three review
layers put six defects on it, one of them dangerous: migrations receive only `projectRoot` and the
contract has no dev-tree guard (`grep -n 'isSameRoot' scripts/update/lib/migration-runner.js
scripts/update/convoke-update.js` returns nothing), so running `convoke-update` inside a Convoke clone
would delete the tracked source this epic exists to preserve. `convoke-install` never runs migrations at
all, so the "reinstall to repair" route would not have been covered either. The orphan is real; it needs
designing, not an AC.

**3. `agent-surface-parity` has no waiver, and that settles "unship ≠ delete".**
`scripts/audit/agent-surface-parity.js:49` declares exit `2` = *"parity BROKEN — an agent or menu code
was removed/renamed"*; `:230` emits `agent removed`. It diffs the last `v*` tag against HEAD and there
is no allowlist, exemption or waiver anywhere in the file — verified by
`grep -n 'waiver\|allowlist\|EXEMPT' scripts/audit/agent-surface-parity.js`, which returns nothing.
**No in-commit companion change to this story's own files can make a deletion green** — a change to the
gate itself could, which is exactly why deletion needs an operator ruling rather than a story. Note also
that the gate's CI wiring waives itself when no `v*` tag exists (`ci.yml:146-150` warns and exits 0), so
"the grep returns nothing" is a claim about the file, not about every path through the job.

That is the finding that sets this epic's scope: **stop packaging it; keep the source in git.** Every
cross-module consumer keeps working, the parity gate stays green, and "internal scaffolding" is
exactly what a tracked-but-unshipped tree is.

## Scope

**In:** one story, one atomic commit — the module stops shipping, every derived artifact moves with
it, the audited documentation stops advertising it, and the Covenant's two genuine worked examples are
replaced. `T150`'s roster question is answered by the same
change: with `EXTRA_BME_AGENTS` gone there is no agent-owned workflow to count, so
`EXTRA_BME_WORKFLOWS` is never added and the three `T150` comments in `scripts/docs-audit.js` are
deleted rather than corrected.

**Out — deletion of the tree.** `git rm -r _bmad/bme/_team-factory/` trips `agent-surface-parity` with
no in-commit remedy (above), and takes `tests/team-factory/`, `package.json:51`/`:56`, two non-TF unit
tests and a shipped bin's dependency with it. If it is ever wanted it is a separate decision at a
release boundary, and it needs an operator ruling on the gate — not a story.

**Out — the nine parked hardening rows** (`T132`, `T134`, `T163`(b), `T165`, `T137`, `T138`, `T166`,
`T141`, `T151`). `tfr`'s gate on them was *"revisit when someone has actually walked the path the
machinery guards."* Unshipping does not walk it. **`T151` is the exception worth noting:** its hazard
is `derivePrefix()` producing `EXTRA_SOMETHING_AGENTS` for a team named `extra-something` — the
generator that creates the hazard is what stops shipping, so `T151` should be re-scoped or closed
alongside rather than parked. That is a backlog action, not story scope.

**Out — `T139`** (`tf-epic-3` closed `done` with no deliverable). A records-and-status problem,
already out of scope in `tfr` for the same reason.

## The open ruling this epic cannot make for the operator

**Empty `EXTRA_BME_AGENTS = []`, or delete the export?** The two fail in opposite directions and the
choice is not mechanical:

- **Empty array.** Zero runtime throws. But twelve sites silently stop asserting: the validator's
  `Standalone bme agent files missing` check becomes unconditionally satisfied
  (`scripts/update/lib/validator.js:359-366`) *and* its own fixture stops seeding
  (`tests/unit/validator.test.js:227`) — both halves of one contract go quiet together, with nothing
  red. The T146 regression guard at `tests/unit/docs-audit.test.js:68` passes while proving nothing,
  because `full` collapses from 12 to 11 and 11 is also the team subtotal.
- **Delete the export.** Loud — it throws at module load. But it is silently coerced at exactly two
  sites (`scripts/lib/agent-manifest-generator.js:299`/`:304` via `|| []`, and
  `scripts/audit/lib/installed-tree.js:291`, which returns `[]` for `undefined` **without**
  recording a malformed finding — `:292` is the line that *does* record one), and at `scripts/update/lib/validator.js:326` it is caught and
  mistranslated into a check failure that `migration-runner.js:146` escalates into an **update
  rollback**.

**A third option exists and this epic recommends it:** delete the export *and* every consumer that
would otherwise be vacuous, so nothing is left asserting nothing and nothing is left to throw. It
costs more edits in the same commit and removes the "standalone bme submodule" extension point
entirely — which is a design decision about whether that mechanism has a future, and therefore the
operator's. **Story `tfu-1-1` is authored with this marked as its blocking AC#0.**

## Two defects the change will expose, which are not its fault

**A correct document will be flagged stale.** `docs/testing.md:102` is
`node --test tests/p0/p0-emma.test.js  # one agent` — a comment in a bash fence. It passes today only
because `EXTRA_BME_AGENTS.length === 1` accidentally makes `1` a legal agent count. Re-derive:

```bash
node -e "const r=require('./scripts/update/lib/agent-registry.js');
const {validCountsFor,expectedCountText}=require('./scripts/docs-audit.js');
const a={...r}; delete a.EXTRA_BME_AGENTS;
console.log('has 1 now:',validCountsFor(r,'AGENTS').has(1),
            '| after:',validCountsFor(a,'AGENTS').has(1));
console.log('remedy after:',expectedCountText(validCountsFor(a,'AGENTS'),'agents'))"
```

The remedy it will print names three counts and cannot be followed for that line. This is `T152`'s
defect class firing on a **shrinking** roster, which the `T152` row does not anticipate. The story
handles the instance; the class is a backlog action.

**A check will go green while wrong.** `CHANGELOG.md` is exempt from stale-reference checking —
`scripts/docs-audit.js:752`, `if (relPath !== 'CHANGELOG.md')`. Its `:143` and `:222` both assert 12
agents, both become false, and nothing reports it. History is not rewritten; a new entry is added and
the two stale sentences are left as the historical claims they are.

## Definition of done

`_bmad/bme/_team-factory/` is absent from the installed tree of a **fresh** install; it is still present
in git; every gate named in §Ordering — **including C14** — is green; and no audited document, shipped
manifest or shipped normative file advertises the Team Factory as a capability an operator can invoke.

**The upgraded-install half moved to `T222` at Round 1.** It was in this DoD while the migration was
AC#8, and `try-fresh-install.sh` — the only gate that packs and installs a real tarball — is fresh-only,
so the clause had no gate behind it here.

**Not in the DoD, deliberately:** that the source tree is deleted, and that `T179`'s *"schedule it when
the factory's status would otherwise mislead someone"* condition has fired. The first is out of scope
above; the second is the operator's call to make at pickup, not this epic's to assert.
