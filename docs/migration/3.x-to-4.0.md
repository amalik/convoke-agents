# Convoke 4.0 Migration Guide — 3.x → 4.0

## What to do

Run `npx -p convoke-agents@latest convoke-update`. That's it.

If you have an older Convoke installed globally, typing `convoke-update` on its own runs *that* copy instead of the current one, and it will stop with a version error. The command above always fetches the current package first, so it works either way.

## What happens

`convoke-update` runs the auto-migration and completes in under 60 seconds. Your agents, skills, workflows, and existing config all continue to work. You don't need to re-read any documentation. You don't need to learn any new agent names or config keys. You don't need to re-run installers.

## What changed (under the hood)

**In 3.x:** Convoke loaded configuration through an internal helper that agents invoked at activation time.

**In 4.0:** Convoke loads configuration directly from `_bmad/{module}/config.yaml` at activation. The internal helper has been retired because it's no longer needed. Your existing config files are automatically migrated to the new loading pattern.

This is a maintenance change that keeps Convoke in sync with upstream BMAD. Nothing about your day-to-day use of Convoke changes.

## What if something goes wrong

If `convoke-update` fails for any reason, re-run it. The migration is idempotent — safe to run twice, three times, or however many times you need. It will resume from where it stopped.

If your agents start behaving differently after the upgrade (producing noticeably different outputs on the same inputs), that's a bug, not expected behavior. Report behavioral surprises to the maintainer.

## What's new (that you might notice)

- **Convoke is now installable through the BMAD community marketplace.** If you have colleagues who use BMAD but haven't tried Convoke, they can install it through the normal BMAD plugin system.
- **Upgrades are checked, and we're specific about what that means.** Convoke verifies on every commit that an upgrade hasn't removed an agent, dropped a menu code, or stopped loading your config — 12 agents, checked automatically. It does **not** verify that agents phrase things identically, and Convoke 4.0 makes no such claim. Saying exactly which of those two you're getting is what "honest" means here. Details: `_bmad-output/implementation-artifacts/v63-4-3-release-record-4.0.md`.

- **`convoke-export` works outside the Convoke repo.** It previously failed in any project but Convoke's own, looking for a packaged template inside *your* project. If you tried it and it errored, try again after upgrading.

That's it. Everything else is internal maintenance.
